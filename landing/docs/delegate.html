Docs / Hand off work

Hand off your first piece of work

You don't fill in a form. You ask the coding agent you already use, in plain language, and it sets the work up for you.

Ask for it in plain language

Once your agent is connected, ask for the work the way you'd ask a colleague:

"Send the failing test suite off to a fast model."

"Have someone else write the changelog while I keep going on the API."

Your agent writes the brief, names the folder the work happens in, and either lets Oga choose the account and model or names one itself. You get an ID back as soon as the work starts. From there it runs on its own account, unattended.

What's worth handing off

Handing off costs you a brief and a wait. It pays for itself on work with its own finish line — build this screen, port this module, review this branch, research this question. It doesn't pay for a rename, a typo, or a one-line change: by the time you've described those, you could have done them.

The same goes for anything you're standing over. Work you'd interrupt every two minutes belongs in your own session.

What it's allowed to touch

Every piece of work carries the area you approved: what it may read, and what it may change. Reading the whole folder and writing to one part of it is the usual shape.

  • Naming a folder covers everything inside it.
  • ** means the whole folder you're working in.
  • A path that doesn't exist yet means only itself. If the work will create files under a new folder, write out/**, not out.

Approving an area once is enough — later work in the same project reuses it without asking again. The area is a permission, not a reading list; which files actually get opened is up to whoever does the work.

Who ends up doing it

Name nothing, and the work uses your default model when you set one. Otherwise Oga chooses from the workers and models you turned on. Name a worker and model when the work needs a specific destination.
