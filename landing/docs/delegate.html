Docs / Delegate a task

Send off your first task

A task is a prompt, a working directory, and an approved set of files. There are two ways to start one - ask your editor agent, or talk to Oga directly from the terminal.

From your editor agent

Once Claude Code, Codex, or OpenCode is connected over MCP, it can call Oga's delegate tool on your behalf. Just ask for the work in plain language:

"Delegate the failing test suite fix to a fast model."

"Send the changelog write-up to opencode while I keep working on the API."

Your agent writes the brief, names a working directory, and either lets Oga pick the account and model or names one explicitly. It gets back a task ID the moment dispatch succeeds - the worker then runs unattended on its own account.

Naming nothing sends the work to your loved model if you've set one; otherwise Oga scores every enabled model on every connected account and picks the best fit for the kind of work described.

From the terminal

oga oga opens a conversation with an assistant that plans in prose and delegates through Oga for you - no editor needed:

oga oga --worker <profile> \
  --goal "I am adding billing to the API. Plan it, and send the mechanical parts out."

The assistant calls delegate with a full brief and a cheap model while you keep typing to it. When a worker finishes, its report lands back in the same conversation.

--print runs the same session without the full-screen terminal, for scripting or a headless run:

oga oga --worker <profile> --print --goal "get the release branch green"

What a task can touch

Every delegated task carries an approved scope - a read and a write list of paths, relative to the working directory. read: ["**"] is the common default; a narrower write list keeps a task's edits inside the directories it's meant to change. Once approved for a project, the same scope is reused on later tasks without asking again.
