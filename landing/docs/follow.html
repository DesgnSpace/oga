Follow a task without paying for it

A delegated task runs unattended. Following it should cost you nothing while it works - Oga gives you a few ways to check in, from free to full detail.

Watch: the free default

oga watch is a background process that sleeps for free and prints one line the moment a task asks a question, fails, or finishes:

oga watch 8f2c1a94-... --timeout 30m &

It connects to the broker's event socket for instant delivery, and falls back to reading the local store if the socket isn't there. In Claude Code, a backgrounded command that exits re-invokes the agent - so running oga watch in the background is the notification. Several task IDs can be watched at once: oga watch <id> <id> <id>.

Inspect: the full record

When you need the complete picture - output, scope, spend, and completion - read one task in full:

oga inspect <task-id>

oga tasks lists today's tasks by state, so you can find one before inspecting it or starting a new one.

Reply: answer a question

A task can pause on a question mid-run - it lands in a needs_input state. Answering it is a job for your editor agent: ask it to reply to the task, and it calls the reply tool on the same provider session so the worker picks up exactly where it left off.

Resume: pick a task back up

A task that failed, was cancelled, or is blocked can be retried on its own session - the same files it already read, the same reasoning it already did, are still there:

oga resume <task-id>
oga resume <task-id> -m "the approved area covers tests - continue there"

A task that already completed can be resumed too, as a follow-up - but an instruction is required, since there's nothing to retry without one:

oga resume <task-id> -m "move the state dot to the title's tail"

Check oga tasks before starting new work. If a task already owns the file or feature you're about to touch, resume it instead of dispatching a duplicate.
