Docs / Where data lives

Everything Oga stores stays on your machine

Oga is a local broker. Everything it remembers lives under ~/.oga, and the only thing that leaves your machine is a task's prompt and files, sent to the provider account you chose for it.

Inside ~/.oga

PathWhat it holds
oga.dbThe SQLite store - tasks, events, profiles, memories. Runs in WAL mode, so oga.db-shm and oga.db-wal sit beside it.
oga.sockThe unix event socket the broker pushes task events on. oga watch and the desktop app both read it.
worktrees/One checkout per task dispatched with worktree: true. See Worktrees & PRs.
oga/Saved oga oga terminal sessions, one JSON file per conversation, so a session reattaches where it left off.
cache/, runtime/Working state the broker keeps between runs.

Configuration files

Settings resolve through three layers, highest first:

  1. <project>/.oga.yaml - the project's own file, resolved from the task's working directory.
  2. ~/.oga.yaml - your personal, user-wide config.
  3. Oga's built-in defaults - discovered accounts and the shipped worker rules.

A missing file at any layer is normal. Run oga config [cwd] to print the effective configuration for a directory, and which file each setting actually came from.

Freeing disk

oga cleanup shows what old, finished task activity would be removed, and deletes nothing until you confirm:

oga cleanup
oga cleanup --delete

Add --delete to also remove the checkout of any finished worktree task past the retention cutoff - the branch it produced is never touched.

Nothing here is shared between machines. Moving to a new Mac means signing back into each provider CLI and re-adding profiles in Oga's Settings screen.
