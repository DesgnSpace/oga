Docs / Worktrees & PRs

Give a task its own branch

A task can run in a checkout of its own instead of your working tree - useful for anything that should land as commits, or whenever more than one task runs against the same repository.

Turning it on

Ask your editor agent to delegate with a worktree, or pass it on the delegate tool directly. The plain form takes every default:

{ "worktree": true }

The worker gets a fresh checkout on a branch of its own, commits there, and never touches your working tree. Two tasks sharing one plain checkout would share one index and overwrite each other's edits - a worktree keeps them apart.

Where it lives

  • Checkout: ~/.oga/worktrees/<task-id>, outside the project so it never shows up in a scan of your repository.
  • Branch: oga/<slug-of-title> by default, created the moment the task is dispatched.
  • Base: the repository's current HEAD, unless a different commit or branch is named.

Everything else - scope, project memories, routing - stays keyed to the original repository, so a worktree task is approved exactly like any other task on that project.

After the task

The checkout stays once the task settles. Review the branch from the original repository and merge it, or throw it away:

git -C <repo> log oga/<slug-of-title>
git -C <repo> merge oga/<slug-of-title>

A task working inside a worktree can commit and push its branch, then open a pull request, the same way you would - oga watch or oga inspect will show a PR link in its report once one exists.

Cleaning up

oga cleanup --delete removes the checkouts of finished, archived tasks past the retention cutoff - it never deletes a branch, so the work survives the checkout being freed. Archiving a task that ran in a worktree removes its checkout at the same time and keeps the branch.
