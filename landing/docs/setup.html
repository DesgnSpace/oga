Docs / Setup

Connect your agent and your accounts

Two things to set up once: point your coding agent at Oga, then tell Oga which provider accounts it's allowed to delegate to.

Connect Claude Code, Codex, or OpenCode

Oga speaks MCP over http://127.0.0.1:7331/mcp. The app's Install MCP button writes a global MCP entry for every installed client it finds - Claude Code, Codex, OpenCode, and Antigravity - and backs up any existing config with a .bak suffix.

Once connected, your agent can see Oga's tools - delegate, tasks, inspect, reply, resume, and the rest - the same way it sees any other MCP server.

Add a profile for each account

On first launch, Oga detects which provider CLIs are installed and lets you add, edit, and enable profiles. No accounts are hardcoded. Each profile stores:

  • Its provider - one of claude, codex, opencode, opencode-2, antigravity, or pi.
  • A default model.
  • Environment variables, with secret-like values (KEY, TOKEN, SECRET, PASS) masked on every surface.

Each profile's account directory comes from the profile, never from the shell Oga was started in - so two profiles never fight over the same login. A Claude profile named claude uses $HOME/.claude; every other worker ID gets its own $HOME/.<worker-id> unless you point it elsewhere. Set CLAUDE_CONFIG_DIR in a profile's environment to reuse a directory you've already signed into:

profiles:
  claude-work:
    env:
      CLAUDE_CONFIG_DIR: $HOME/.claude-work

Enable models and pick a default

The Settings screen controls which workers and models can receive work - a model must be enabled for a worker before Oga can send a task there. Mark one worker/model pair loved to make it the default for work that names no model.

From the terminal:

oga config
oga love

To set the default explicitly, name the worker and model:

oga love opencode/openai/gpt-5.6-luna

Use oga love --clear to let routing choose per task again. Add --global to any love command to set the user-wide default instead of the current project's.

Everything here can be checked from the terminal - oga config [cwd] prints the effective profiles, models, and routes for a directory, and which file each setting came from.
