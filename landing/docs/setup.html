Docs / Set up accounts

Set up the accounts that do the work

Two things, once: tell Oga which accounts it may hand work to, then point the coding agent you already use at Oga.

Let your coding agent reach Oga

Oga's Install MCP button adds Oga to every coding agent it finds on your Mac — Claude Code, Codex, OpenCode, and Antigravity. Anything already configured is backed up first.

Setting one up by hand instead? Point it at http://127.0.0.1:7331/mcp. Either way, your agent can then hand work to Oga the way it uses any other tool you've connected.

Add an account

The first time you open Oga, it looks for the provider tools you already have and offers to add an account for each. Nothing is set up in advance. Every account holds:

  • Which tool it runs — Claude Code, Codex, OpenCode, Antigravity, or Pi.
  • The model it uses when nothing else is named.
  • Any environment values it needs. Anything that looks like a key, token, secret, or password is hidden everywhere Oga shows it.

Each account keeps its own sign-in, so two accounts never fight over the same login. A Claude account named claude uses ~/.claude; every other one gets a folder of its own. To point an account at a folder you've already signed into, set CLAUDE_CONFIG_DIR on it:

profiles:
  claude-work:
    env:
      CLAUDE_CONFIG_DIR: $HOME/.claude-work

Choose who gets work that names nobody

Settings controls which accounts and models can receive work at all — a model has to be turned on before Oga will send anything to it.

Mark one account and model as loved to make it the default for work that names nothing. From the terminal:

oga love claude:opus

Run oga love on its own to see what this project does today. oga love --clear goes back to choosing per piece of work, and --global applies your choice to every project instead of this one.

oga config prints what a folder actually resolves to — accounts, models, and which file each setting came from.
