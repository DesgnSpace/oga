Docs / Set up accounts

Set up the accounts that do the work

Two things, once: tell Oga which accounts it may hand work to, then point the coding agent you already use at Oga.

Let your coding agent reach Oga

Oga's Install MCP button connects the coding agents it finds on your Mac. Existing connections are backed up first.

Setting one up by hand instead? Point it at http://127.0.0.1:7331/mcp. Your agent can then hand work to Oga like any other connected tool.

Add an account

On first open, Oga directs you to connect your AI before you delegate. You can also open Settings → Workers to add an account you already use. Every worker holds:

  • Which provider tool it runs.
  • The model it uses when nothing else is named.
  • Any environment values it needs. Anything that looks like a key, token, secret, or password is hidden everywhere Oga shows it.

Each worker can use its own sign-in. Add environment values in the worker settings when a provider needs them.

Choose who gets work that names nobody

Settings controls which workers and models can receive work. A model has to be turned on before Oga can select it.

oga love pins the worker and model that runs work nobody named an account for. Set it once, and every piece of work that leaves worker and model blank lands there instead of wherever Oga would otherwise guess.

Pin a default

Mark one account and model as loved to make it the default for work that names nothing. From the terminal:

oga love claude:opus

Give it a reasoning effort too, as a third part of the name:

oga love claude:opus:high

Name more than one destination and Oga tries them in order, moving on the moment one can't take the work — out of quota, unreachable, or not offering that model:

oga love opencode:muse claude:opus

Pin a kind of work

Send one kind of work somewhere else with --when, leaving everything else on the default:

oga love opencode:muse --when ui
oga love codex:beast --when backend,database

A kind is a subject — ui, ux, backend, database, docs, tests, review, research, refactor — or a class of work: context, mechanical, build, reasoning, general. Oga reads the kind off the task itself by default. A coding agent that already knows it's handing off a UI change, say, can name the kind directly instead — with --kind from the terminal, or its own kind option — rather than leave Oga to guess from the wording. When a task fits two rules, the one naming its subject wins over one naming only how demanding the work is.

general is the catch-all: a rule pinned to it takes everything no other rule claimed, not only the work that reads as nothing in particular. Pin general and one subject, and everything outside that subject still lands on the general rule:

oga love opencode:muse --when ui
oga love claude:opus --when general

See what's set, and clear it

Run oga love on its own to see what this project sends where today, listed in the order the rules take work:

oga love

oga love --clear drops every rule and goes back to choosing per piece of work. Add --when to drop only the rule for those kinds:

oga love --clear --when ui

Project or every project

Every command above applies to the project you're standing in. Add --global to set it for every project instead. That's the fallback: a project's own rules, once it has any, replace the global list whole rather than add to it.

oga love claude:opus --global

oga config prints what a folder actually resolves to — accounts, models, and which file each setting came from.
