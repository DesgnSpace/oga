Getting started

Oga is a local broker that hands work to other coding agent CLIs — Claude Code, Codex, OpenCode, Antigravity, and Pi — so they run in parallel on their own accounts while you keep working. This page covers install through your first delegated task.

Install

Requires macOS 14 or later.

curl
curl -fsSL https://downloads.desgn.space/oga/install.sh | sh
Homebrew
brew install --cask DesgnSpace/tap/oga

Either installs the Oga menu-bar app and puts the oga command on your PATH. Confirm the broker is running:

curl http://127.0.0.1:7331/health

First run

  1. Open Oga. On first launch it finds which provider CLIs you already have installed and lets you add, edit, and enable profiles — one per provider account. No accounts are hardcoded; log into each provider's CLI yourself first.
  2. Click Install MCP. It writes an MCP entry pointing at http://127.0.0.1:7331/mcp into every coding agent it finds — Claude Code, Codex, OpenCode, and Antigravity. Existing configs are backed up with a .bak suffix.
  3. Restart your coding agent so it picks up the new MCP server.

One worker/model pair can be marked loved, which becomes the default for work that doesn't name one:

oga love opencode/openai/gpt-5.6-luna

Delegate a task

Delegating happens from inside your coding agent, not from a separate CLI command. Ask the agent you're already talking to — Claude Code, Codex, whichever you connected — to hand off a bounded piece of work:

Delegate: implement the CSV export endpoint in api/export.py

Your agent calls Oga's delegate MCP tool with a prompt and a working directory. Oga picks a model, starts a sandboxed worker on a different account, and hands back a task ID immediately — dispatch, not completion. The worker keeps running after your agent moves on to something else.

Watch, inspect, resume

A delegated task runs unattended. Follow it from the same terminal your agent uses:

Wait for it to settle
oga watch <task-id> &

It prints one line the moment the task asks a question, fails, or finishes, and costs nothing while it waits. In Claude Code, a backgrounded command finishing is itself the notification.

List today's tasks
oga tasks
Read one task's full record
oga inspect <task-id>
Retry a failed or blocked task
oga resume <task-id>

Worktrees and PRs

Add worktree: true to a delegated task and Oga gives it its own checkout and branch, so the worker commits without ever touching your working tree. Use it whenever the work should land as commits, or whenever more than one task runs against the same repository.

The checkout stays after the task settles, on branch oga/<slug> by default. Review and merge it, or open a PR from it, like any other branch:

git -C <repo> log oga/<slug>

Where data lives

Everything Oga keeps stays on your machine, under ~/.oga: the SQLite task store, worktree checkouts, and the unix socket the broker uses to push task updates. Nothing is sent to a third-party server — tasks run through the provider CLIs you already have installed, on their own accounts.
